## 1. Typecho 1.2.1 保存路径（上游源码核实）

证据：`v1.2.1` tag 的 `var/Widget/Contents/Post/Edit.php`、`var/Widget/Base/Contents.php`。

`writePost()` 顺序（Edit.php:286–294）：

```text
write 插件钩子（save 前）
  → publish()：insert/update contents → setCategories → setTags → attach → applyFields
  → finishPublish 插件钩子
  → （随后才 redirect / exit）
```

关键事实：

1. **核心写入没有任何事务包裹**。`Base/Contents.php` 的 `insert()`（:110）和 `update()`（:199）直接 `$this->db->query(...)`；分类、标签、自定义字段各是独立 autocommit 查询。计划假设的"核心保存是原子的"不成立——原子性必须由插件自己建立。
2. 全部写入发生在同一 PHP 请求内、同步执行，`finishPublish` 在 redirect 之前触发。这给插件留出了"包住整个保存过程"的窗口。
3. `Db::query()`（`var/Typecho/Db.php`:372）接受裸 SQL 字符串并直传适配器（Mysqli.php:102），插件可以发 `START TRANSACTION` / `COMMIT`。
4. **读写句柄分离**：`Db::selectDb($op)` 的连接池按 op 键控（Db.php:214），即使单库配置，READ 与 WRITE 也是两条物理连接。事务、行锁（`SELECT ... FOR UPDATE`）必须显式走 `Db::WRITE` 句柄，不能假设默认连接。
5. 自定义字段经 `applyFields()`（Base/Contents.php:295）逐条 `setField`，也在 publish() 内部、同一窗口内。
6. 安装默认引擎 InnoDB（install.php:927）；`contents.text` 为 `longtext`（install/Mysql.sql:52），译文版本表正文同用 `longtext` 即可容纳最长文章。

## 2. 原子保存协议的可行形态

**中文编辑侧（源版本登记）**：i18n 插件在 `write` 钩子里对 WRITE 句柄 `START TRANSACTION` 并锁定该 CID 的 `source_state` 行；核心写入落在这条连接的事务里；`finishPublish` 钩子里插件写入新 `sourceRevision`/`sourceHash` 后 `COMMIT`。任一步失败或请求中断 → 连接关闭 → 整体回滚，内容与源版本登记同生共死。草稿路径同理（`finishSave`）。

**worker / 校对回写侧（CAS）**：独立连接开事务，`SELECT ... FOR UPDATE` 锁定 `source_state` + `translation_head`，核对 `expectedSourceRevision`/`expectedSourceHash`/`expectedTranslationRevision`，不匹配则标 superseded，匹配则插版本、移指针、同事务插 `publish_outbox`，提交。不依赖任何 Typecho 钩子，纯 SQL 可实现。

风险与边界：

- 包裹事务把核心写入也纳入了插件事务，插件自身的 bug 可能导致文章保存失败（故障面扩大）。必须把插件事务代码控制在最小范围，失败时抛出而非静默吞掉。
- `Response::redirect()` 在 `finishPublish` 之后执行，COMMIT 先于响应结束，时序安全。
- `register_shutdown_function` 路径（AutoRebuild 的 meta 监听）不参与内容保存，不冲突。

## 3. 快照模型（本地代码核实）

证据：`scripts/export-typecho-snapshot.js`、`scripts/sync-typecho.js`。

- 两处都已用 `REPEATABLE READ` + `START TRANSACTION WITH CONSISTENT SNAPSHOT` 在单事务内读取 contents/relationships/fields/metas 四表。接入翻译版本表 = 在同一事务里追加 SELECT，模型直接兼容，**无需新建一致性机制**。
- 注意：两个脚本表名前缀**写死 `typecho_`**。翻译表若按方案"前缀从 Typecho 配置取得"，这两个脚本也要同步改（或由导出器探测），否则快照会漏读。
- `translation_version` 的选定版本应随快照导出（只读），离机构建不持有生产写凭据——与现状一致。

## 5. worker 连接方案

证据：`compose.1panel-cms.yml`、`docker/rebuild-api/server.js`、`typecho/usr/plugins/AutoRebuild/Plugin.php`。

- builder 容器现用 `TYPECHO_RO_DB_USER`（只读）经 onepanel 网络访问 MySQL。翻译 worker 放入同一 compose 项目，新建**独立数据库用户**：对翻译专用表 SELECT/INSERT/UPDATE，对 `typecho_contents`/`typecho_fields` 只读，无其他权限。
- outbox 发送器复用 AutoRebuild 既有签名发送：同一 `webhook_secret` 文件（只读挂载进 worker）、同一 allowlisted 端点 `http://rebuild-api:9000/hooks/rebuild`。rebuild-api 的 202/accepted、pending/dirty 合并、nonce 防重放逻辑（server.js `enqueue()`）原样复用；**目标版本幂等键需放入 event payload**，rebuild-api 目前只透传 event 字段，需确认合并逻辑不依赖未知字段（P1 实测项，已写入计划退出条件）。
- worker 不需要公网接口，不持有 CDN/发布权限。
