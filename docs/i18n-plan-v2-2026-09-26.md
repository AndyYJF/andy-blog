# andy-blog 国际化方案 v2：对抗审查修订版

日期：2026-09-26。状态：**设计已修订，尚未实施或通过运行验证**。

本文件替代 [原计划](i18n-plan-2026-09-26.md)，以 [对抗审查](i18n-adversarial-review-2026-09-26.md) 的 I18N-01～07 为修订依据。原计划和报告保留历史记录，不再作为相互冲突的实现依据。

## 1. 已确定的目标和边界

- 首次双语上线：全部公开文章都有完成校对的英文全文，覆盖率按候选快照核算。
- 后续：**中文先发布，英文异步补齐**。翻译服务失败、缺译、旧译文不阻塞中文发布。
- 中文地址、既有 routeId、评论键和中文 feed GUID 不变。英文使用同域 `/en/`。
- 保持 Typecho 内容源、Astro 静态站、Pagefind、Waline、生产机导出快照、离机构建、单个完整 release 原子切换。
- 不引入第二个英文站部署系统，不在构建期间请求翻译模型，不从旧 dist 拼接页面。
- “不阻塞中文”限定于翻译任务与**可识别、可隔离的单条英文内容故障**。共享代码错误、数据库故障、磁盘不足、未知渲染异常仍会正常阻止发布，不承诺整站基础设施故障下中文也能上线。

公开文章范围沿用现有公开条件：已发布、未设密码且 `kind=post`；`allowFeed=false` 的公开文章也翻译，只是不输出到 RSS/llms。草稿、撤回、密码内容不公开。闲话本期保持中文并在英文导航明确标识。

公开站点为 `https://www.andy-y.cn`。构建机经生产机访问；连接参数与凭据不入仓库。本方案依赖本地源码核对，生产最新数量、实际部署代码和数据库事务能力尚待实施前确认。

## 2. 面向访客的行为

| 情况 | 中文 | 英文 |
|---|---|---|
| 新文章还没有译文 | 正常发布，提示英文准备中 | 不生成伪英文占位页，不提供无效切换链接 |
| 英文初稿生成但未校对 | 不受影响 | 仅后台预览，不公开 |
| 中文已修改，旧英文仍可用 | 新版正常发布 | 继续显示旧英文，详情和列表标注待更新及版本时间 |
| 新英文完成校对与验证 | 不受影响 | 经既有发布流程更新，URL/GUID 不变 |
| 单条英文损坏 | 不受影响，前提是能够安全隔离 | 回退有效旧版本；无有效版本则暂不生成 |
| 英文被编辑明确停用 | 中文仍可保留 | 下一次成功发布移除，重建不会自动恢复 |
| 原文撤回、删除或设密码 | 按现有发布流程移除 | 同一处理该变更的 release 移除全部译文及发现入口 |

普通过期译文不自动 noindex、不退出列表/搜索/sitemap；仍是同篇文章的对应版本时保留 hreflang。中文大幅重写、旧译文已不再对应时，编辑明确设置“不再等价”以去除双向 hreflang，但不自动删除可读旧页。重大错误或敏感信息走“停用”，与单纯待更新分开。

英文列表、相关文章、搜索摘要、llms 明确表达待更新状态。普通重译不会制造新的 RSS 项，也不令英文列表反复增减。

## 3. URL 与界面覆盖

| 内容 | 英文 URL |
|---|---|
| 首页、文章列表 | `/en/`、`/en/posts/` |
| 文章及分类/标签 | `/en`＋原 canonicalPath |
| 分页、归档 | `/en/page/<n>/`、`/en/archive/` |
| 关于、DN42、友链、最近在听 | 对应 `/en/.../` |
| 邀请页 | `/en/linuxdo/`，请求仍发送到 `/linuxdo/claim` |
| RSS、llms | `/en/rss.xml`、`/en/llms.txt`、`/en/llms-full.txt` |

语言切换使用真实链接，由生成的语言映射查找，不给所有地址机械加前缀。没有对应页面时明确提示。URL 决定语言，不按 IP 或浏览器设置强制跳转。初版跨语言使用完整页面导航，避免旧语言搜索/评论实例残留。

共用模板通过 locale 参数获取字典，覆盖导航、页脚、搜索、评论及只读评论、日期/字数、复制、目录、图表、播放器、邀请页错误/加载/成功状态及 aria 文案。首页简介与项目事实保持一致。歌曲与艺术家名称、品牌名称按原名保留。

文章翻译包括标题、摘要、正文、图注和 alt。代码、公式、URL、命令参数、短代码机器参数不翻译。关键中文截图保留原图并补英文说明。中文阅读统计保持现状，英文以词数估算阅读时间。保留系统字体、暗色、reduced-motion 与现有布局。

## 4. 内容存储：同一 CID，独立版本记录

修订决定：不再把可覆盖的单个 `i18n_en` JSON 当作完整发布状态。**由 Typecho 插件管理同数据库中的专用翻译表**，仍属于 Typecho 内容系统；不是额外英文 post，不更改中文文章身份。

采用专用表的原因是版本比较、人工修订保护和 outbox 需要可靠事务；避免同时维护 fields 和专用表两份正式译文。表名前缀从 Typecho 配置取得，不写死生产前缀。正文使用能容纳最长文章的 UTF-8 文本字段。

最小逻辑数据结构：

| 记录 | 核心字段及职责 |
|---|---|
| source_state | CID、sourceRevision、sourceHash、可见性版本；记录插件观察到的源版本，正式公开条件仍以内容表为准 |
| translation_head | CID＋locale 唯一键；translationRevision、draftVersionId、approvedVersionId、publicationState（enabled/disabled）、equivalenceState |
| translation_version | 不可变 versionId；标题/摘要/正文、sourceRevision/hash、contentDigest、术语版本、作者、校对时间、渲染验证结果 |
| translation_job | 幂等任务键、状态、lease、尝试次数、下次执行时间、源及预期译文修订号 |
| publish_outbox | eventId、目标版本、通知状态、尝试次数、关联 release 及观察结果 |
| publication_ledger | CID＋locale 的首次可供发布时间、首次成功上线时间、最近成功版本及 release |

版本正文不可原地改写：任何人工修改产生新版本。校对记录绑定 contentDigest；修改内容后必须重新校对。worker 只能写草稿，不能移动 approved 指针。数据库记录不包含供应商 API 密钥。

### 原子保存协议（修复 I18N-02）

1. 翻译任务记录 `expectedSourceRevision`、`expectedSourceHash`、`expectedTranslationRevision`，读取固定源文本。
2. 回写在事务中按统一顺序锁定源状态及译文 head，重新核对当前源、可见性和两个修订号。
3. 任一不匹配则标记任务 superseded，结果不覆盖草稿或人工版本；需要时为最新源重新排队。
4. 匹配时新增版本、移动 draft 指针并递增 translationRevision，原子提交。
5. 人工校对使用同样的比较协议；批准具体 digest 后移动 approved 指针，并在**同一事务**插入 publish_outbox。

原文变化后的旧 approved 版本可继续读，但判为 outdated。中文标题/正文/翻译相关说明参与 sourceHash，译文字段、保存时间不参与；权限与封面等共享字段单独处理。

**必要实现前提**：P0 必须确认 Typecho 中文编辑、自定义字段保存及插件事务的准确边界。中文编辑与译文回写必须采用同一源版本协议；只在 finishPublish 后补写修订号不具备该原子保证。确认数据库引擎、实际保存路径及事务连接，做真实交错保存验证后再启用自动回写。若无法可靠接入，先交付手动导入/校对原型并将自动回写列为未实现，不能声称凭 sourceHash 已解决竞态。

直接 SQL 改正文不属于受支持编辑路径；补偿扫描可发现漂移，但不替代事务。正式写内容应经 Typecho 插件支持的保存路径。

## 5. 异步任务和发布通知

### 最小运行结构

Typecho 插件提供后台编辑、任务领取和回写入口。一个可替换供应商的翻译 worker 独立于 Astro 构建进程运行；建议由构建机运行，经已有受控连接调用生产侧服务。无需新增公网写接口，也不给 worker 全库写权限。具体认证、连接与服务用户在部署配置中定义。

任务队列与 outbox 使用同一现有数据库，不为首版引入 Redis、消息总线或额外调度平台。worker 持有有期限的 lease，崩溃后任务可重新领取；耗尽重试后显示失败，不无限付费重试。模型、预算、校对责任人仍需实施时确定。

### 两条补偿路径（修复 I18N-03）

```text
中文发布/修改
  ├─ 现有 AutoRebuild → 最新快照 → 构建并发布中文
  └─ 翻译任务 → 草稿 → 校对+验证 → approved 与 outbox 原子保存
        → outbox 发送器 → AutoRebuild → 构建并补齐英文
```

- **翻译补偿**：扫描公开源与任务/approved 的版本差异，找回漏入队任务。
- **发布补偿**：比较期望可发布版本和 current release manifest，找回已保存却没上线的译文；不再只检查“是否完成翻译”。

AutoRebuild 继续唯一发布入口。outbox 发送器重复使用既有签名发送函数，不在 worker 内直接切换 release。HTTP 202 只标记 accepted；看到对应版本进入 current manifest 才记为已上线。状态分别显示“待通知、已接受、构建中、源站已切换、CDN 待确认”，避免伪报公网已经更新。

每个通知以目标版本作为逻辑幂等键；已有 pending/dirty 合并继续使用。崩溃或响应丢失允许重复投递，但不重复创建相同目标事件。accepted 后超过构建预算仍未进入 manifest 时，按退避策略核对并重投；阈值以实际构建耗时设定，不能每分钟重建全站。

如果候选将该版本隔离为 render-rejected，outbox 进入“需要修复”，不由发布补偿反复重建。同版本重试必须有修订、运行环境变化或显式重试事件。若 approved 被新版本取代、文章撤回或英文停用，旧通知终止为 superseded/cancelled。

## 6. 内容故障隔离与构建（修复 I18N-01）

保持单个完整 release，不拆成独立中英文部署。增加译文渲染验证和一次有界回退：

1. 译文从草稿晋升为可发布版本前，使用同版本的 Markdown/HTML 渲染插件与安全清洗链验证；校对与机器渲染验证各自记录，不互相替代。
2. 验证结果绑定 contentDigest 和 renderFingerprint（相关 lockfile、插件配置及转换代码修订）。渲染环境变更使旧验证失效，必须在候选中重新验证。
3. 对所有选中的英文内容做带 versionId 的预渲染，收集能明确归因于英文输入的失败。选择同快照内已批准、未停用且本轮验证通过的旧版本；没有则暂不生成该英文详情。
4. 使用最终选择清单重算列表、分页、搜索、sitemap、RSS、llms 和语言映射，再运行完整 Astro build。该清单同时驱动验证与最终 manifest。
5. 若完整构建仍出现明确归因于单条英文内容的失败，排除/回退对应版本，最多再做一次完整构建；第二次失败正常中止。无法归因、共享模板/插件代码错误、路径冲突、中文错误及基础设施错误直接失败，不捕获成“英文可以跳过”。

错误必须携带 phase、sourceFile、versionId、locale 和归因类型；不能只凭错误文本中出现 `/en/` 判断。归因机制本身是实现风险：Astro/插件抛错不天然带 versionId，逐条预渲染能覆盖正文渲染错误，但 RSS/sitemap/语言映射等聚合阶段的英文相关失败可能无法归因，此时按上一条规则正常失败、不隔离。P2 必须先做一次注入故障 spike（一条英文渲染失败＋一条中文正常更新），验证归因与隔离真实可行，再实现完整回退逻辑；spike 证明聚合阶段失败不可归因时，接受该路径全站失败并记录为已知边界。被隔离的译文在后台显示原因，不给内容打 reviewed/成功假标记。首次全量上线时任何缺译/隔离均不满足上线条件；日常模式允许缺译并发布中文。

候选产物整体重建和 checksum 后切换；仅从 Typecho 快照选择版本，不读取历史 HTML 当作内容源。失败保留 current，撤回内容不能被作为英文回退素材。

这使单条坏译文具有明确退路，但仍不承诺任意代码故障下的中文发布可用性。

## 7. 撤回、停用和回滚（修复 I18N-04）

### 普通撤回：明确采用最终一致

本期不实现跨 CMS、文件系统、CDN 的原子撤回。用户撤回后立即停止新的翻译任务与批准；**静态页面在下一次成功处理该撤回的 release 切换后从源站移除**，边缘缓存清理另行跟踪。

正在构建的快照可能早于撤回。切换前可做可见性版本比较，发现过期则放弃候选并重排，但这只是缩小窗口；比较后仍可能发生编辑，不把该检查宣称为绝对保证。保留 dirty 后续任务，并用期望状态与 current manifest 的补偿扫描确保最终下线。

后台显示“撤回待发布 → 源站已移除 → 缓存清理已提交/已确认”；构建失败时明确显示撤回尚未完成，不能显示已下线。相同规则覆盖英文单独停用、密码保护、删除和回滚后状态重核。

### 紧急撤回：独立运维能力

若内容需要立即禁止访问，进入明确授权的紧急处置：源站针对具体中英文路径拒绝访问、精确刷新边缘缓存、核查搜索资源及公开正文端点，必要时采取对应 CDN 访问限制。实际清理时间由服务状态决定，不能保证已下载副本消失。

该流程单独写入 runbook；不为国际化首版新增一套“全局强一致撤回锁”。紧急封禁不依赖 release，自动回滚不能撤销它。实际 nginx 变更仍通过项目配置生成器与正常检验，不手改生成配置。

普通回滚前比较目标 release 与当前撤回/停用集合；已知会重新暴露内容时拒绝直接回滚，选择修复候选或先执行授权封禁。普通模式仍承认 CMS 并发修改窗口，不将一次预检当作原子保障。

## 8. Manifest 与检查适配（修复 I18N-05）

保持现有 CID 路由表为中文路径事实来源；语言清单从其派生，不分配第二套 routeId。现有 manifest.entries 若被旧脚本按 CID 索引，应保持其原有中文语义，新增带版本号的 localizedEntries，由相关新消费者明确接入。

每个语言输出条目至少包含：

```text
entryKey = kind:sourceCid:locale
sourceFile / sourceDigest
canonicalPath / outputFile
sourceRevision / translationVersionId / contentDigest
translationStatus = current | outdated | missing | disabled | render-rejected
renderExpected / discoverable / equivalent / allowFeed / allowComment
selectedVersionId / rendererFingerprint
```

同一 CID 的中文、英文是两个输出身份。renderExpected=false 的条目只进入状态报告，不要求存在页面；renderExpected=true 缺少页面必须失败。路径必须规范化且落在 dist 内，禁止目录穿越及重复 canonical。

`scripts/render-gate.js` 改为按清单的 outputFile 读取实际产物，不再靠目录名/slug 猜测 URL；同时核对 canonical、正文和图表等对应内容证据。不能用中文页面替代英文验收。旧中文特例保留为中文回归用例。

同步调整 render、RSS、stage4 的实际生产入口；按所修改数据结构核对 stage6/stage8 的语言键、固定数量与 CID 唯一性假设，不机械扩大全部历史检查。增加独立英文清单的正反例即可，无须新建另一套综合门禁系统。

## 9. 搜索、SEO、评论与旧译文（修复 I18N-06）

- Pagefind 移除全站强制 zh，按真实 HTML lang 建索引；中文/英文 UI 选择对应索引。实际语言键通过构建产物核实。
- 普通 outdated 译文仍参与英文检索和发现，但提示版本滞后；disabled、missing、render-rejected 且无有效回退的页面不参与。
- 每种语言自指 canonical。只有实际生成且 equivalent=true 的对应页面输出互相 hreflang；关系由同一清单生成。
- 语言切换链接与 SEO alternate 是两个概念：不等价的旧译文仍可提供注明版本的人工阅读链接，不强行输出等价标注。
- sitemap 使用真实规范页面及该页面有效变更时间；RSS/txt、404、邀请页及不可发现分类的英文地址同样排除。
- 普通过期标记是页面内容变化，sitemap lastmod 可反映提示发生时间；“翻译更新时间”仍显示实际译文时间，不混为一谈。
- Waline 共享原 commentKey，界面本地化；权限由当前源与 release 写入开关共同决定，评论原文不翻译。
- 分享图沿用 thumb/default。raw → sanitize、安全 URL、h1 降级等原渲染约束保持。

## 10. 英文 RSS：迟到译文也有明确的首次发布语义（修复 I18N-07）

中文 RSS 完全保持原语义。英文 GUID 与 URL 固定，不因更新、回滚或重新翻译改变。

**区分三个时间**，避免在静态 feed 构建时依赖尚未发生的成功切换：

| 字段 | 含义 |
|---|---|
| sourcePublishedAt | 中文原文发布时间，保留并显示 |
| translationAvailableAt | 第一版英文完成校对与渲染验证、首次获得发布资格的时间；在数据库中一次性赋值 |
| translationFirstPublishedAt | 第一次成功进入 release 的实际时间，由发布记录回填；用于审计和后台，不倒逼同次 feed 重写 |

英文 RSS 的 pubDate 和排序使用 **translationAvailableAt**，并明确其为“英文版本可供发布时间”；不是虚构实际切换时间。这个选择修正审查建议中“先成功上线才能生成同次 RSS 时间”的循环依赖。每次重译不重置上述首次时间；feed 摘要标出原文发布时间，避免把翻译说成新原创。注意：首次全量导入时大量译文的校对时间集中，pubDate 会扎堆，阅读器可能一次性刷出全部历史英文文章——这是可预期的首版现象，不视为故障。

首版英文 RSS 收录全部 allowFeed=true 且已生成的英文文章，不复用中文最近 10 篇窗口；这样晚完成的老文章译文不会被原文排序截断。首次全量导入可以显示全部历史英文项，这是明确选择。后续若规模要求分页/归档，再单独设计并保留迟到译文覆盖；本期不擅自加入截断。

成功切换记录由生产侧记录器以 releaseId＋manifest digest 幂等保存，并将实际发布时间回填 publication_ledger；记录器失败时从持久切换记录补偿，不能把当前轮询时间伪装成首次上线时间。已有首次记录不因回滚清空。准确时间缺证据时标记未知，不捏造。

RSS 不能从阅读器收回已下载条目；撤回时只保证后续站点/feed 不再输出。llms 按当前可发布内容生成，outdated 版本附说明，allowFeed=false 始终排除。

## 11. 发布接入、CDN 与数据迁移

1. P0 核对实际 Typecho 保存路径、数据库引擎、导出器和构建机环境。生产读取不等于写授权。
2. 使用有版本的可重复迁移建立翻译表、唯一约束与索引；先在隔离数据库验证，正式启用前备份。回滚前端不删除译文表，旧流程可忽略它们。
3. `export-typecho-snapshot.js` 与直接 DB sync 在同一一致性事务中读取源和翻译版本；fixture 包含相同 schemaVersion。CMS 预览读取同版本契约。
4. off-box 构建接收冻结快照，不持有生产数据库写凭据，也不调用翻译模型。译文验证服务与实际 build 使用一致 renderFingerprint。
5. release 带 localizedEntries、隔离报告及完整 checksum。补偿器使用实际 current manifest，不只用“构建返回成功”。
6. 新英文固定 URL 同步更新 CDN purge、preheat 和 stage4；动态 URL 从清单获取。
7. 精确刷新前后 release 的相关 URL 并集，包含消失页面、分页、feed、llms、语言关系页与搜索资源；只预热当前可访问的规范页面。不可缓存邀请领取结果或预热领取 API。
8. 旧英文版本的回退也重新生成当前权限与所有发现产物，不保留已撤回内容的旧索引。
9. 不清空持久图片/图表缓存。候选失败保持 current。生产写入、发布和清 CDN 仍需在实施会话明确授权。

P0 建议先投入约 0.5–1 人日，完成后再给 P1–P5 排期。P0 期间必须并行确定翻译供应商、预算与校对责任人——P1 worker 实现与 P3 全量翻译排期都依赖它们，不敲定则 P0 退出后仍无法排期。旧版 7–12 人日估计撤回为未验证粗估，不在本版继续作为可依赖总工期；实际成本取决于 Typecho 保存路径接入及人工校对量。本方案不包含新建跨系统强一致撤回平台，避免将它混入首版工期。

## 13. 最小验收矩阵

| 对应问题 | 必须验证的反例 | 通过条件 |
|---|---|---|
| 01 | 一条英文渲染失败，同时另一篇中文更新 | 安全隔离后中文发布；报告被隔离英文；未知错误不被吞掉 |
| 02 | worker 回写期间中文变化或人工修订英文 | 旧任务比较失败，人工内容与 approved 版本不被覆盖 |
| 03 | 保存 approved 后进程崩溃、通知超时、accepted 后构建失败 | outbox/manifest 补偿最终发布；失败不被报为上线，无无限重建 |
| 04 | 撤回分别发生在快照后、预检后、切换后 | 如实显示窗口；后续处理撤回的 release 双语消失，CDN 状态分开 |
| 05 | 同 CID 双语产物，故意删除英文文件 | 检查器精确报告英文缺失，中文不能代替 |
| 06 | 批量中文微调，尚未重译 | 英文列表/搜索保留旧版并标记，显式停用才下线 |
| 07 | 老文章译文迟于 11 篇新译文批准并上线，再重译 | 出现在英文 feed，GUID 与首次可供发布时间稳定 |
| 通用 | 私密/撤回、allowFeed=false、非法路径、快照损坏 | 正确排除；结构性错误正常失败 |

另做受影响页面的桌面、390px/320px、亮暗、搜索重挂载、语言切换、评论、目录/hash、复制和邀请页隔离环境检查。运行实际被修改脚本的针对性测试以及正式候选既有必要检查，不空跑无关历史门禁。

首次报告源快照、公开总数、current/outdated/missing/disabled/render-rejected 数、人工校对清单。日常报告额外显示最久待译时间、outbox 滞留及对应 current release。文档闭环不等于这些验收已经通过。
