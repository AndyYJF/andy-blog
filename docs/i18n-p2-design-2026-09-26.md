# i18n P2 设计：同步、英文集合与故障隔离（2026-09-26）

对应总方案 `i18n-plan-v2-2026-09-26.md` 第 5/6/8/12 节。P2 交付：独立译文集合、localizedEntries 清单、同管线预渲染验证、有界回退、render-gate 改造。**退出条件 = 注入故障 spike 通过**：一条英文渲染失败被隔离、同时一篇中文正常发布、无法归因的错误照常让全站失败。

## 1. 范围划定

- 翻译对象只有 `post` / `page`（moments、linuxdo、friends 等不译，英文区不生成）。
- P2 只做最小可用 `/en/` 页面（共享布局、英文正文、lang="en"）；字典、完整 UI 本地化、全量校对是 P3。
- 英文 RSS/llms/SEO/hreflang/CDN 是 P4。P2 阶段英文页 `noindex`，不输出 hreflang，不进 sitemap/RSS。
- outbox `accepted → live` 的回填（manifest 观察）是 P4 发布回执的一部分，P2 不做。

## 2. 版本选择协议（sync 时执行）

输入（同一一致性快照内读取，见 §3）：`i18n_source_state`、`i18n_translation_head`、approved 指向的 `i18n_translation_version`、`i18n_publication_ledger`。

对每个公开中文 post/page（cid）计算英文条目状态：

| translationStatus | 条件 | 本轮是否生成页面 |
|---|---|---|
| `disabled` | head.publication_state = 'disabled' | 否 |
| `missing` | 无 head 或 approved_version_id 为 NULL | 否 |
| `render-rejected` | 预渲染验证失败（§6），写入本轮选择清单 | 否 |
| `outdated` | approved 版本的 source_revision < source_state.source_revision | 是（旧版本继续可读） |
| `current` | 两者相等 | 是 |

选择结果写入 `astro/src/generated/i18n-selection.json`（构建机生成、随候选产物走，不手改）：

```json
{
  "snapshotEpoch": 1790000000,
  "rendererFingerprint": "sha256:...",
  "locales": ["en"],
  "entries": [
    {
      "entryKey": "post:30:en",
      "kind": "post", "sourceCid": 30, "locale": "en",
      "translationStatus": "current",
      "sourceRevision": 3, "translationVersionId": 12,
      "contentDigest": "sha256...",
      "sourceFile": "src/content/en-posts/my-post.md",
      "canonicalPath": "/en/posts/my-post/",
      "outputFile": "en/posts/my-post/index.html",
      "renderExpected": true, "discoverable": false,
      "equivalent": true, "allowFeed": true, "allowComment": true,
      "translationAvailableAt": 1790000123,
      "rejectReason": null
    }
  ]
}
```

- `discoverable: false`：P2 期间英文页一律 noindex、不进任何发现产物（P4 翻转）。
- `renderExpected: true` 的条目在 dist 中缺文件 = 门禁失败；`false` 只进状态报告。
- URL 规则：`canonicalPath = '/en' + 中文 canonicalPath`。中文 CID 路由表仍是唯一路径事实来源，英文不分配第二套 routeId。
- 英文 `feedGuid = 中文 feedGuid + '#en'`（固定，不随重译变化）。
- `commentKey` 与中文相同（Waline 共享评论区，计划 §9）。

## 3. 快照与同步改造

**export-typecho-snapshot.js**：在同一 `REPEATABLE READ + CONSISTENT SNAPSHOT` 事务内追加 4 个查询：`i18n_source_state`、`i18n_translation_head`、`i18n_translation_version`（只取被 approved 指向的行 + 各 head 的 draft 指针用于后台展示，不带未 approved 正文以缩小快照）、`i18n_publication_ledger`。快照 JSON 增加 `i18n` 键与 `schemaVersion: 2`。表不存在（旧环境）时退化为空 `i18n` 并照常工作（向后兼容）。

**部署前提**：生产只读用户（TYPECHO_RO_DB_USER）需要这 4 张表的 SELECT 授权，否则 builder 导出失败。

**sync-typecho.js**：

1. 生成中文如旧。
2. 按 §2 协议选择英文版本，把选中版本的 `body` 当过与中文**相同的结构转换**（`convertShortcodes`、`normalizeJoeTaskMarkers`、`normalizeHeadings`、`remapFenceLangs`、strip markdown marker）。**不做** `repairKnownContent`（那些是按 cid 写死的中文文本补丁，套到译文上会误伤）。
3. 写入 `astro/src/content/en-posts/`、`astro/src/content/en-pages/`（与中文同规则原子换装；文件名沿用中文 slug，保证 outputFile 可推导）。
4. frontmatter 复用 commonSchema 字段（kind/title/legacyCid/canonicalPath/commentKey/feedGuid/allow*/pubDate/updatedDate/categories/tags/sourceFormat/cover/description），外加：`locale: 'en'`、`sourceCid`、`sourceRevision`、`translationVersionId`、`translationStatus`、`translationAvailableAt`、`sourcePublishedAt`（中文 created）。`pubDate` 用 translationAvailableAt，`updatedDate` 用版本 proofread_at。`title` 用译文标题。categories/tags 沿用中文结构（P3 再决定是否译名）。
5. 产出 `i18n-selection.json`（§2），含 `rendererFingerprint`（§6）。
6. 被排除（missing/disabled/rejected）的 cid 不生成文件；旧的英文文件随目录换装自然消失——英文下线 = 下次成功 release 移除，与撤回语义一致。

## 4. Astro 侧最小实现

- `content.config.ts`：新增 `enPosts`、`enPages` 两个集合，schema = commonSchema + §3.4 扩展字段（`locale: z.literal('en')` 等）。
- `astro/src/pages/en/posts/[id].astro`、`en/[...page].astro`：复用现有文章布局组件，传入 `locale="en"`；布局按 locale 设 `<html lang>`、加 `<meta name="robots" content="noindex">`（P2 专用，P4 移除）。标题/日期等少量硬编码中文 UI 字符串先用英文内联（P3 换字典）。
- `en/index.astro` + `en/posts/index.astro`：简单列表（linked title + translationStatus 徽标），不做分页美化。
- 不改 `astro.config.mjs` 的 i18n 配置（Astro 内置 i18n 路由对现有中文路由侵入大，手写 /en/ 页面更外科手术）。

## 5. localizedEntries 与 render-gate 改造

**生成**：构建后、门禁前，新脚本 `scripts/gen-release-manifest.js` 扫描 dist + 读 `i18n-selection.json`，产出 release manifest 的 `localizedEntries`（= 选择清单每条 + 实际 outputFile 存在性核对结果）。中文条目不进 localizedEntries（保持现有 manifest.entries 中文语义不变，计划 §8）。

**render-gate.js** 改为清单驱动：

1. 读 `i18n-selection.json`；对 `renderExpected=true` 的每条按 `outputFile` 取产物做原有检查（article 存在、正文比例、mermaid 数量与产物文件）。
2. 不再从「目录名猜 URL」；中文条目改为：sync 在 `i18n-selection.json` 同目录额外写 `zh-manifest.json`（sourceFile→outputFile 映射，同样结构，无 i18n 字段），render-gate 统一走清单。Joe 两个中文特例 fixture 原样保留为中文回归用例。
3. `renderExpected=true` 缺产物 → 失败；`render-rejected` 条目要求产物**不存在**（生成了反而是错误，说明隔离失效）。

## 6. 归因机制与有界回退（spike 核心）

**共享管线**：把 `astro.config.mjs` 里 markdown processor 的 remark/rehype 插件数组与 sanitize schema 抽到 `astro/src/lib/markdown-pipeline.mjs`，astro.config 与预渲染脚本都从它导入——验证环境与构建环境同一份代码，这是 renderFingerprint 的基础。

**rendererFingerprint** = sha256(`astro/package-lock.json` + `astro.config.mjs` + `src/lib/markdown-pipeline.mjs` + `src/plugins/*`)。环境变更 → 指纹变 → 旧验证失效，候选重新验证。

**预渲染脚本** `scripts/prerender-en.js`（构建机、astro build 之前运行）：

1. 读 `i18n-selection.json`，对每条 `renderExpected=true` 的英文 md，用共享管线 render 成 HTML（含 mermaid/beoe，走 Playwright）。
2. 逐条捕获异常，产出结构化记录：`{ entryKey, versionId, phase: 'prerender', ok, error?, attribution: 'content' }`。一条失败 → 该条 `translationStatus=render-rejected` + `rejectReason`，回写选择清单，**继续**验证其余条目。
3. 正文级静默丢弃（mermaid 失败整篇消失类）在预渲染里用与 render-gate 相同的正文比例规则检测，同样归因到条目。
4. 预渲染通过但正式 build 仍失败、且错误信息**精确包含**某英文条目的 `sourceFile` 路径（phase=build, attribution=file-path-match）→ 隔离该条目，重跑一次完整构建；第二次仍失败 → 正常中止。其他一切错误（共享模板、聚合阶段 RSS/sitemap、基础设施、中文内容）→ 不隔离，直接失败。

**build-release.sh** 流程变为：

```text
sync → prerender-en（隔离坏译文）→ astro build → gen-release-manifest → gates → package
              ↘ build 失败且可归因单条英文 → 标记 rejected → 重试一次 → 再失败则中止
```

worker/后台展示：`render-rejected` 状态经下次 worker 补偿扫描写回 `translation_head.last_reject_reason`（轻量做法：rejected 记录落在 selection json，随 release manifest 持久，P4 发布回执时一并回写 DB）。

## 7. Spike 计划（P2 退出条件）

在构建机对候选快照执行：

1. **注入 A（英文渲染失败）**：把一篇已 approved 译文版本改成会炸管线的内容（首选：非法 katex 公式 + 未闭合 mermaid fence，哪个稳定抛错用哪个；备用：注入 rehype-raw 无法解析的 HTML）。同时 **注入 B（中文正常更新）**：改一篇中文正文（测试库/快照层注入，不动生产 CMS）。
2. 期望：A 被隔离为 render-rejected 且报告含 versionId/phase/原因；B 正常构建发布；release 切换成功；门禁对「rejected 却存在产物」校验为通过（产物确实不存在）。
3. **注入 C（无法归因错误）**：临时改坏一个共享布局组件。期望：构建失败、候选中止、current 保持，错误不被吞成「英文跳过」。
4. spike 中若发现聚合阶段（列表/sitemap/RSS 数据准备）的英文相关失败无法归因 → 接受全站失败，记入本文档「已知边界」。

## 9. 部署与授权点

- 生产只读用户加 4 张 i18n 表 SELECT（一次性 GRANT，随 P2 部署执行）。
- P2 全程不动生产 CMS 数据；英文页 noindex，公网影响为零，可在正常 release 里灰度。
- 首次带英文条目的 release 切换仍走既有授权流程。
