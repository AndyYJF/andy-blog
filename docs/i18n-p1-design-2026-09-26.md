# i18n P1 设计：版本表、CAS 协议、worker 与 Kimi 接入

日期：2026-09-26。依据：`i18n-plan-v2-2026-09-26.md` 第 4、5、12 节 + `i18n-p0-findings-2026-09-26.md` 已核实事实。本文是 P1 的实现规格；P2（构建接入）不在本文件范围。

## 1. 组件与位置

| 组件 | 位置 | 职责 |
|---|---|---|
| 迁移脚本 | `scripts/i18n-migrate.js` | 有版本、可重复地建/升 6 张翻译表 + 1 张迁移记录表 |
| Typecho 插件 | `typecho/usr/plugins/I18n/` | 包裹事务登记源版本、入队翻译任务、后台审批/停用、Action 端点 |
| 翻译 worker | `docker/i18n-worker/`（Node，进 `compose.1panel-cms.yml`） | 领取任务、调 Kimi、CAS 回写、outbox 发送、两条补偿扫描 |

供应商：Kimi（Moonshot）。`KIMI_BASE_URL` / `KIMI_MODEL` / `KIMI_API_KEY_FILE` 全部走环境变量，密钥只以文件挂载，不进数据库、不进仓库。默认值在实施配置里定，代码不写死模型名以外的任何端点假设。

## 2. 表结构（前缀 `{p}` 取 Typecho 配置，当前生产为 `typecho_`）

全部 InnoDB / utf8mb4。正文用 `longtext`（P0 已核实最长 101,017 字符）。

```sql
{p}i18n_migrations(version INT PRIMARY KEY, applied_at INT UNSIGNED NOT NULL);

{p}i18n_source_state(
  cid INT UNSIGNED PRIMARY KEY,
  source_revision INT UNSIGNED NOT NULL,      -- 每次受包裹保存 +1
  source_hash CHAR(64) NOT NULL,              -- sha256(title \0 text)
  visibility VARCHAR(16) NOT NULL,            -- publish/draft/private/hidden/password…
  content_type VARCHAR(16) NOT NULL,          -- post/page/post_draft…
  saved_at INT UNSIGNED NOT NULL);

{p}i18n_translation_head(
  cid INT UNSIGNED NOT NULL,
  locale VARCHAR(8) NOT NULL,
  translation_revision INT UNSIGNED NOT NULL DEFAULT 0,  -- 每次草稿回写 +1
  draft_version_id BIGINT UNSIGNED NULL,
  approved_version_id BIGINT UNSIGNED NULL,
  publication_state ENUM('enabled','disabled') NOT NULL DEFAULT 'enabled',
  equivalence_state ENUM('equivalent','not_equivalent') NOT NULL DEFAULT 'equivalent',
  updated_at INT UNSIGNED NOT NULL,
  PRIMARY KEY(cid, locale));

{p}i18n_translation_version(
  version_id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  cid INT UNSIGNED NOT NULL,
  locale VARCHAR(8) NOT NULL,
  translation_revision INT UNSIGNED NOT NULL, -- 写入时 head 的新 revision
  title TEXT NOT NULL,
  summary TEXT NULL,
  body LONGTEXT NOT NULL,
  source_revision INT UNSIGNED NOT NULL,
  source_hash CHAR(64) NOT NULL,
  content_digest CHAR(64) NOT NULL,           -- sha256(title \0 summary \0 body)
  glossary_version VARCHAR(40) NOT NULL DEFAULT '',
  author VARCHAR(40) NOT NULL,                -- worker:kimi:<model> / human:<uid>
  proofread_at INT UNSIGNED NULL,
  proofreader VARCHAR(40) NULL,
  render_verdict VARCHAR(32) NULL,            -- P2 渲染验证回填
  render_fingerprint CHAR(64) NULL,
  verified_at INT UNSIGNED NULL,
  created_at INT UNSIGNED NOT NULL,
  KEY idx_cid_locale (cid, locale, version_id));
  -- 版本不可变：不提供 UPDATE 路径，人工修改 = 新版本

{p}i18n_translation_job(
  job_id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  idem_key VARCHAR(80) NOT NULL UNIQUE,       -- translate:{cid}:{locale}:{sourceRevision}
  cid INT UNSIGNED NOT NULL,
  locale VARCHAR(8) NOT NULL,
  status ENUM('queued','leased','done','failed','superseded','cancelled') NOT NULL DEFAULT 'queued',
  expected_source_revision INT UNSIGNED NOT NULL,
  expected_source_hash CHAR(64) NOT NULL,
  expected_translation_revision INT UNSIGNED NULL,  -- 领取时快照 head
  lease_owner VARCHAR(64) NULL,
  lease_until INT UNSIGNED NULL,
  attempts INT UNSIGNED NOT NULL DEFAULT 0,
  max_attempts INT UNSIGNED NOT NULL DEFAULT 5,
  next_run_at INT UNSIGNED NOT NULL,
  last_error VARCHAR(500) NULL,
  created_at INT UNSIGNED NOT NULL,
  updated_at INT UNSIGNED NOT NULL,
  KEY idx_pick (status, next_run_at));

{p}i18n_publish_outbox(
  event_id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  idem_key VARCHAR(96) NOT NULL UNIQUE,       -- publish:{cid}:{locale}:{versionId}
  cid INT UNSIGNED NOT NULL,
  locale VARCHAR(8) NOT NULL,
  version_id BIGINT UNSIGNED NOT NULL,
  status ENUM('pending','accepted','needs_fix','superseded','cancelled','live') NOT NULL DEFAULT 'pending',
  attempts INT UNSIGNED NOT NULL DEFAULT 0,
  next_retry_at INT UNSIGNED NOT NULL,
  release_id VARCHAR(48) NULL,                -- P2 观察 manifest 后回填
  observed_at INT UNSIGNED NULL,
  last_error VARCHAR(500) NULL,
  created_at INT UNSIGNED NOT NULL,
  updated_at INT UNSIGNED NOT NULL,
  KEY idx_send (status, next_retry_at));

{p}i18n_publication_ledger(
  cid INT UNSIGNED NOT NULL,
  locale VARCHAR(8) NOT NULL,
  translation_available_at INT UNSIGNED NULL, -- 首次批准，只写一次
  first_published_at INT UNSIGNED NULL,       -- 首次进入 current release，P2 回填，只写一次
  last_live_version_id BIGINT UNSIGNED NULL,
  last_live_release VARCHAR(48) NULL,
  updated_at INT UNSIGNED NOT NULL,
  PRIMARY KEY(cid, locale));
```

`publish_outbox.status` 的 `building`/`live` 细分依赖 P2 的 manifest 观察；P1 只推进到 `accepted`，`live` 由 P2 回填，状态机字段先留全。

## 3. 源版本登记（插件包裹事务）

利用 P0 核实的时序：`write` 钩子 → 核心全部写入（同一 WRITE 句柄）→ `finishPublish`/`finishSave` 钩子 → redirect。

```text
write 钩子:        START TRANSACTION（Db::WRITE 句柄）
                   SELECT ... FOR UPDATE 锁定 {p}i18n_source_state 该 cid 行（无行则记下待插）
finishPublish/Save: 计算 source_hash；INSERT 新行或 UPDATE revision+1/hash/visibility
                   若结果公开（publish 且无密码）→ INSERT IGNORE 翻译任务（幂等键含新 revision）
                   COMMIT
任意异常:           ROLLBACK 并重新抛出——内容保存与源登记同生共死，不静默吞错
finishDelete/mark:  同事务把该 cid 的 queued/leased 任务与 pending outbox 标记 cancelled；
                   已 live 的版本保留（撤回下线由 P2 的清单驱动，表记录不删）
```

约束：只用 `Db::WRITE` 句柄发事务与锁语句（P0 发现读写句柄是两条物理连接）。worker 与审批全部走独立连接，不共享 Typecho 句柄。

## 4. CAS 回写与审批

worker 回写（每个任务）：

```text
BEGIN
  SELECT ... FOR UPDATE: source_state(cid)、translation_head(cid,locale)
  核对 source_state.source_revision/hash == job.expected_* 且 head.translation_revision == job.expected_translation_revision
    不匹配 → 任务标 superseded（需要时按最新源重新入队）→ COMMIT，结束
  匹配 → INSERT translation_version（新 revision = head.revision+1）
        UPDATE head: draft_version_id、translation_revision+1
        UPDATE job: done
COMMIT
```

审批（后台，管理员）：

```text
BEGIN
  SELECT ... FOR UPDATE: translation_head
  核对目标版本 content_digest == 页面提交的 digest（防审批到被替换的版本）
  UPDATE head: approved_version_id = 该版本
  UPDATE version: proofread_at/proofreader
  INSERT publish_outbox（幂等键 publish:{cid}:{locale}:{versionId}，INSERT IGNORE）
  INSERT publication_ledger 或补 translation_available_at（仅在 NULL 时写，保证只记首次）
COMMIT
```

worker 永远只写草稿指针；approved 指针只有审批端点能动。停用（disable）只改 head.publication_state，不删版本。

## 5. worker 流程

```text
循环（间隔 WORKER_POLL_MS，默认 15s）：
  1. 领取：BEGIN; SELECT ... FOR UPDATE SKIP LOCKED 取 status='queued' AND next_run_at<=now
          且未超 max_attempts 的 1 条 → leased(lease_owner=实例id, lease_until=now+120s,
          expected_translation_revision=当前 head.revision); COMMIT
  2. 读源：按 cid 读 contents，重算 source_hash，与 expected 不符 → superseded
  3. 调 Kimi：chat/completions，系统提示词 + 术语表（glossary 文件 sha 即 glossary_version）
     输出严格 JSON {title, summary, body}；代码块/URL/短代码机器参数不译（提示词约束 + 回写前校验占位符数量一致）
  4. CAS 回写（第 4 节）；失败/超限 → failed，next_run_at 指数退避；耗尽 → failed 终态，不无限付费重试
  5. outbox 发送：扫 pending/accepted 到期事件 → 复用 AutoRebuild 签名 POST rebuild-api
     （payload 增加 i18n:{cid,locale,versionId} 字段；202 → accepted 记 attempts）
  6. 补偿扫描（低频，默认 10min）：
     翻译补偿 = 公开 contents ⋈ source_state 有 revision 但无对应 job/approved → 补入队
     发布补偿 = approved 版本无 pending/accepted/live outbox → INSERT IGNORE 补事件
```

崩溃恢复：lease 过期（lease_until < now）的 leased 任务视为可重新领取（扫描时先 `UPDATE ... SET status='queued' WHERE status='leased' AND lease_until<now`）。accepted 后是否上线由 P2 manifest 观察判定，P1 不重投 accepted 事件。

## 6. rebuild-api 去重行为（P1 实测项）

`docker/rebuild-api/server.js` 的 `enqueue()` 对未知字段透传进 event（`event: payload.event` 之外的字段不读取也不拒绝），合并语义只看 pending/dirty 文件存在性：构建中 → dirty，否则 pending。两个快速连续事件 = 最多两次构建，不会因 i18n 字段产生循环。nonce 防重放要求每次发送用新 nonce——重投同一 outbox 事件必须重新生成 ts+nonce，幂等性由 outbox 行的 idem_key 保证，不靠 rebuild-api。

实测方式：本地 `node --test` 直接 import `server.js` 的 `createServer`，临时 RUNTIME_DIR，连发两个事件验证 pending→dirty→构建后 dirty 转 pending 的行为（对照 `host/blog-rebuild-1panel.sh` 的 dirty 处理）。

## 7. 隔离验证方案

生产 MySQL 8.4.5 上建临时库 `i18n_p1_test`（同引擎同版本，与业务库完全隔离），`node --test scripts/i18n-p1.test.js` 用 mysql2 直连跑反例：

1. worker 回写途中"编辑"又保存（source_revision 已 +1）→ CAS 失败、任务 superseded、草稿不覆盖
2. 人工审批后旧 worker 以相同 sourceHash 回写 → translation_revision 不匹配 → 人工版本不被覆盖
3. 审批提交后、outbox 发送前 kill worker → 重启后发布补偿补发事件且幂等键不重复
4. lease 中途过期被另一实例领取 → 原实例 CAS 时 revision 不符，安全落败
5. rebuild-api 本地实测（第 6 节）

全部通过后 DROP 该临时库。生产正式建表在 P1 收尾单独授权执行，执行前备份。

## 8. 验证结果（2026-09-26，已通过）

隔离库 `i18n_p1_test`（生产 MySQL 8.4.5，已 DROP）+ 本地 rebuild-api 实测，`scripts/i18n-p1.test.js` 7/7 通过：

1. happy path：领取 → CAS 回写只移动 draft 指针，approved 不动
2. 编辑保存与 worker 翻译交错 → 旧任务 superseded，无旧版本写入
3. 人工批准与 worker 回写交错 → 过期 worker CAS 失败，人工版本与最新草稿均不被覆盖
4. 批准后 worker 崩溃 → outbox 事件持久，重启后补偿不重复创建
5. lease 过期 → 第二实例领取成功，原实例 CAS 落败
6. 翻译补偿幂等补入队（重复扫描不产生重复任务）
7. rebuild-api 真实去重：pending → building 中 dirty 合并；同 nonce 重放被拒（401）——重投必须每次生成新 ts+nonce，幂等性由 outbox idem_key 承担

修复的实现 bug：claim/收割/outbox 扫描的时间比较从本地时钟改为 DB 服务器时钟（跨机时钟偏移会让新任务“永远不到期”）。生产 worker 与 MySQL 同机，但单一时间权威更稳。

PHP 侧三个文件（Plugin/Action/panel）已在生产 Typecho 容器 `php -l` 通过。

**剩余部署步骤（需当次授权）**：生产库备份 → 生产跑 `i18n-migrate.js` → 建 worker 限定权限用户 → 部署 I18n 插件并启用 → 启动 i18n-worker 服务。
